# 코드에 없는 사실

이 저장소를 만들면서 알게 된 사실 가운데 코드(소스, 주석, 테스트, 설정 파일)만 봐서는 알 수 없는 것을 적었습니다. 코드로 분명한 내용은 여기에 없습니다. 문서에 더 자세한 설명이 있으면 그 위치를 괄호로 적었습니다.

모두 2026-11-22에 확인한 내용입니다. 단가, 도구 동작, 저장소 상태는 그 뒤로 달라졌을 수 있으니, 중요한 판단에 쓰기 전에 다시 확인하십시오.

## Claude Code 기록 형식

Claude Code 2.1.330에서 확인했습니다.

- Claude Code는 세션마다 `~/.claude/projects/<프로젝트>/<세션 id>.jsonl` 파일에 한 줄에 JSON 하나씩 기록하며, 토큰 사용량은 `type`이 `"assistant"`인 줄의 `message.usage`에 있습니다. 필드 대응표는 `docs/INGEST_API.md`의 "Claude Code 기록에서 이벤트 만들기"에 있습니다.
- 응답 하나가 내용 블록마다 한 줄씩 기록되어 같은 `message.id`가 여러 줄에 나옵니다. 확인한 기록에서는 그 줄들의 `usage`가 모두 같았으므로, 응답 하나는 한 번만 세어야 합니다(`docs/INGEST_API.md`).
- `message.model`이 `"<synthetic>"`인 줄은 실제 API 호출이 아니므로 사용량으로 세지 않습니다(`docs/INGEST_API.md`).
- Claude Code는 같은 파일에 `type`이 `"cost-state"`인 줄도 남깁니다. 여기에 세션 누적 비용 `totalCostUSD`와 모델별 `modelUsage`(토큰 수, `costUSD`)가 있고, 여러 번 기록되므로 파일의 마지막 줄이 최종값입니다.
- 메시지별 `usage` 합계가 마지막 `cost-state`의 토큰 수와 같은 세션에서는, 단가표로 계산한 비용이 `costUSD`와 소수점 아래까지 일치했습니다(세션·모델 조합 32개). 단가표를 고친 뒤에는 이 대조로 검증할 수 있습니다.
- Claude Code가 내부적으로 쓰는 보조 모델(Haiku) 호출은 `assistant` 줄로 남지 않고 `cost-state`에만 나타납니다. 그래서 기록을 읽어 보내는 방식으로는 수집되지 않습니다(`docs/INGEST_API.md`, `README.md`의 "알려진 한계").
- 그 때문에 생기는 비용 차이는 확인한 세션 28개에서 대부분 0.1센트였고, 가장 큰 경우가 5센트(세션 비용의 1% 미만)였습니다(`docs/INGEST_API.md`).
- 확인한 기록(컴퓨터 한 대, 2026년 8~11월)에서 캐시 쓰기는 거의 전부 1시간 보관(`ephemeral_1h_input_tokens`)이었습니다. 캐시 쓰기가 5분 보관으로만 들어온다면 수집 쪽에서 보관 시간 구분을 빠뜨렸는지 확인해 볼 만합니다.
- 실행 중인 세션의 모델과 추론 수준은 세션 기록의 마지막 `assistant` 줄(`message.model`, `effort`)에서 확인할 수 있고, 세션 id와 추론 수준은 환경변수 `CLAUDE_CODE_SESSION_ID`와 `CLAUDE_EFFORT`에도 있습니다. 커밋에 AI 정보를 적을 때 씁니다.

## 단가

- 단가 가운데 실제 비용 기록과 대조해 확인한 것은 `claude-fable-5`와 `claude-fable-5-1`(입력, 출력, 1시간 캐시 쓰기, 캐시 읽기), `claude-haiku-4-5`(입력, 출력)뿐입니다. 그 밖의 모델과 5분 캐시 쓰기, 빠른 모드·배치·미국 내 추론 배수, 긴 프롬프트 단가, 웹 검색, 어드바이저 비용은 가격 문서의 값을 옮기기만 했습니다(`README.md`의 "추정 비용과 단가표").

## 측정값

합성 데이터 200만 행으로 잰 값입니다.

- 리뷰에서 제안된 인덱스 두 개, `(ts, user_id, model, project)`와 `(session_id, ts)` 부분 인덱스는 조회 속도를 바꾸지 못했고(SQLite가 쓰지 않았습니다) 데이터베이스 크기만 약 58% 늘렸습니다. 같은 제안이 다시 나와도 측정 없이 추가하지 않습니다.
- 1년 전체를 조회하면 리포트용 인덱스가 있어도 주 조회에 약 1.8초, 세션 조회에 약 1.6초가 걸렸습니다(서버를 거치지 않고 SQL만 잰 값). 인덱스 교체로 줄일 수 있는 것은 여기까지였습니다.
- 저장 용량은 한 행에 300바이트 안팎으로 추정합니다(실제 기록의 문자열 길이 기준, 100만 행에 약 300MB). 문자열이 짧은 합성 데이터에서는 테이블이 행당 120바이트, 리포트용 인덱스가 93바이트였습니다(`README.md`의 "저장 용량").
- 버전 1 데이터베이스를 버전 2로 올리는 데 약 5초가 걸렸습니다(`README.md`의 "업그레이드").
- 동시 전송은 임시 스크립트로 한 번 확인했습니다. 전송자 4개가 같은 6,000건을 서로 다른 묶음으로 겹쳐 보내는 동안 조회와 CLI 토큰 발급을 함께 실행했고, 모든 이벤트가 한 번씩만 저장됐습니다. 이 시험은 자동 테스트에 들어 있지 않습니다.

## 확인되지 않았거나 저장소에 없는 것

- 화면(`web/`)에는 자동 테스트가 없습니다. 헤드리스 Chrome을 DevTools 프로토콜로 구동해 세션 쿠키를 넣고, 밝은 화면·어두운 화면·모바일 너비의 스크린샷과 DOM 값으로 확인했습니다.
- 실제 기록을 다시 보내 대조한 스크립트, 스크린샷 스크립트, 성능 측정 스크립트는 저장소에 없습니다. 세션 임시 폴더에서 만들어 쓰고 남기지 않았습니다.
- 빌드와 테스트는 macOS(arm64)의 Rust 1.100에서만 했습니다. 리눅스에서의 빌드와 실행, 크로스 컴파일은 확인하지 않았습니다.
- 밝은 화면에서 계열 색 가운데 청록, 노랑, 분홍은 바탕과의 명도 대비가 3:1에 못 미칩니다(팔레트 검증 결과). 이 색들은 값을 색 말고 다른 방법으로도 읽을 수 있을 때만 쓸 수 있으므로, 차트의 "표로 보기"를 없애면 안 됩니다.
- Anthropic 문서에 따르면 `usage.iterations`에는 거부된 뒤 대체 모델로 다시 처리한 시도(`fallback_message`) 같은 항목도 올 수 있습니다. 이 서버는 항목마다 행을 저장하므로, 과금되지 않은 시도가 섞이면 비용이 실제보다 높게 추정될 수 있습니다(`README.md`의 "알려진 한계").

## 정해진 것과 아직 정하지 않은 것

- 수집 프로세스는 이 저장소에 두지 않고 별도 저장소에서 만들기로 했습니다. 아직 만들어지지 않았습니다(`README.md`).
- 수신 형식은 기존 수집기에 맞추지 않고 이 대시보드가 정하기로 했습니다. 그 규칙이 `docs/INGEST_API.md`입니다.
- 오래된 기록의 보존 기간(자동 삭제나 요약 여부)과 비용의 원화 환산 표시는 리뷰에서 제기됐지만 아직 정하지 않았습니다.

## 저장소 이력

- `velar-agent/usage-dashboard`는 2026-11-22에 새로 만든 저장소입니다. 그 이름을 쓰던 기존 대시보드는 `velar-agent/old-usage-dashboard`로 이름이 바뀌었습니다.
- 기존 대시보드는 Python과 SQLite로 만든 별개의 프로젝트이며 이 저장소와 이력을 공유하지 않습니다. 두 저장소를 합치지 않았습니다.
- 기존 대시보드는 서비스별 사용 한도(%)를 `service`, `metric`, `value` 기록으로 `/api/ingest`에 받고, 수집기 `token-usage-collector`가 그 형식으로 보냅니다. 이 대시보드의 `/api/v1/events`와는 형식이 달라 그 수집기를 그대로 쓸 수 없습니다.
- GitHub는 이름을 바꾼 저장소의 옛 주소로 오는 가져오기와 푸시를 새 이름의 저장소로 넘겨 줍니다. 옛 이름으로 새 저장소를 만들면 그때부터 옛 주소는 새 저장소를 가리킵니다. 두 주소에 `git ls-remote`를 해서 같은 커밋이 나오면 아직 넘겨 주는 상태입니다.
- 기존 대시보드의 서버는 매일 00:00(KST)에 자기 저장소의 `main`을 `git pull --ff-only`로 받아 운영에 반영합니다. 그 서버의 원격 주소가 아직 옛 이름(`usage-dashboard`)을 가리킨다면 이 저장소를 당기려다 실패합니다. 주소를 바꿨는지는 확인하지 못했습니다.

## 커밋과 푸시

- 이 저장소의 커밋은 작성자와 커미터를 `velar-agent <velar-agent@users.noreply.github.com>`로 남깁니다(기존 저장소의 커밋과 같은 표기). 컴퓨터의 전역 git 설정이 다른 이름이면 커밋할 때 따로 지정해야 합니다.
- 이 저장소에 쓸 수 있는 것으로 확인된 GitHub 계정은 `velar-agent`입니다. 다른 계정의 자격 증명으로 푸시하면 403으로 거부됩니다.
- macOS에서는 git이 시스템 설정의 키체인 도우미를 사용자 설정의 도우미보다 먼저 씁니다. 키체인에 다른 계정이 저장되어 있으면 그 계정으로 인증되며, `git credential fill`로 어느 계정이 쓰이는지 확인할 수 있습니다.
- `gh auth login`에서 HTTPS와 git 인증 연동을 고르면, 그 뒤 git의 https 푸시가 로그인한 계정으로 인증됩니다.
- 전역 `prepare-commit-msg` 훅이 설정된 컴퓨터에서는, 메시지를 `-m`이나 `-F`로 주지 않은 커밋에서 훅이 변경 내용으로 커밋 메시지 초안을 만들어 편집 화면에 넣습니다. 메시지를 직접 줄 때 `-m`이나 `-F`를 쓰면 훅이 건너뜁니다.

## agy 리뷰

agy 1.5.14에서 확인했습니다.

- `agy`는 `-p "<요청>"`을 붙이면 대화 없이 한 번 실행하고 답을 출력합니다. 리뷰는 저장소 폴더에서 `agy --dangerously-skip-permissions --model "Gemini 3.8 Flash (High)" -p "변경사항에 대해서 리뷰해주세요"`로 요청했습니다.
- agy가 로그인되어 있지 않으면 `-p` 실행은 인증을 60초만 기다리다 실패합니다. 로그인은 대화형 터미널에서 미리 해 두어야 하며, 한 번 하면 키링에 저장되어 이후 실행에 쓰입니다.
- agy는 모든 권한을 허용한 상태에서도 리뷰 요청 두 번 모두 파일을 고치지 않았고(실행 전후 체크섬으로 확인), 두 번째에는 스스로 `cargo test`를 실행했습니다.
